## 改动与范围

当前 V2 runner 每步原本在 CPU Gloo group 上对 6×DP 的稀疏元数据矩阵做 SUM。实验启用 `VLLM_DP_METADATA_SHM=1` 后，每 rank 发布自己的 6 个字段，再收集其他 rank，保持原来的 field-major 连续 int32 布局。下游 graph、padding 和 ubatching 决策保持一致。

复用已有 `MessageQueue`：每 rank 一个单写者多读者队列、每队列两个 1KiB 槽。数据走 POSIX SHM，本机 IPC 用于唤醒；Gloo 仅用于初始化句柄/同节点检测。每步带 sequence 和 sender，整体超时 60 秒；异常不在半步中途回退 backend。默认开关关闭，不能共享 SHM 时整体保留原 Gloo 路径；销毁 group 时关闭队列。

这不是完全没有 IPC/socket 的自定义原子共享内存实现。没有修改 EP GPU 通信、MoE 分块、权重、量化或采样策略。

## 方法

TY19 B300×8，TP1/DP8/EP8，DeepSeek-V4.1-Flash-1017，DSpark5；max_num_seqs=132/rank，max_num_batched_tokens=1320，FULL_DECODE_ONLY，max_capture=792。EPLB symm_mem，redundant=16，window=1000，step=3000，async=true。保留上一轮 DeepGEMM M64 candidate（sha256 c14a91db28ab64def3d52102518b59015ca3ba3dee58a88c1c59710e039570a0）。镜像 sha256:ad1bf5e74168f03f841d701f2b4e1fe183e9341b4389f67db6ee803c3ade61eb。

TY18 四个共享 L2 DEP2 Prefill；TYCPU gateway 51003，隔离 channel16。四种固定任务、约128k输入，max_tokens=8192，temperature=0，自然EOS。两客户端分片，各3CPU/4GiB。到时取消，不排空；没有 profiler。

基线与 SHM 都按128→256→256→128，每轮90秒。SHM为新启动实例，正式测量前另跑90秒256并发预热（conditioning归档，排除于结果表）；基线已长期运行。EPLB开启、映射没有固定，重启/专家重排/请求构成可能影响差异；两轮结果不作为统计显著性或严格单变量归因。

总输出TPS由八rank generation counter在共同开始30秒后到最早截止前的采样差分计算，计入窗口内所有生成token。单请求TPS为全轮完整请求的输出token/首次至末次非空SSE时间；两个口径样本和时间窗不同，不能用并发×单请求均值精确还原总吞吐。完整稳态内请求单独列出。

- 独立CPU八进程、同镜像：reduce两轮均值约11.75ms，SHM约0.073ms。计时包含SHM输出tensor构造；不是模型吞吐预测。
- 15,360次值/布局检查，含乱序到达、两槽反复复用、负数/零值；序号错误所有rank拒绝；缺少一个rank时其余七rank按时超时。
- 实际旧/新完整DP函数对照96场景×2种skip模式×8rank，共1536次一致；覆盖空闲、mixed graph、padding、ubatching及sentinel。graph manager为确定性double，GPU图执行另由本次服务启动与负载验证。
- ruff检查、格式检查及git diff --check通过。没有编译新CUDA或C++扩展。
- 原环境文件和parallel_state.py已有额外修改，部署在运行版本上叠加本补丁，未用dev文件覆盖掉既有改动；prepared.json记录四个源码哈希及配置检查。
