## 方法与配置

TY18 四个 DEP2 Prefill，TY19 TP1/DP8/EP8 Decode，8×B300，DeepSeek-V4.1-Flash-1017，DSpark5，EPLB 保持开启。使用同一组四任务约 128k 输入、相同网关隔离 channel 16。输出 `max_tokens=8192`，自然 EOS，不设置 `ignore_eos`。

每版本顺序为 128→256→512→512→256→128，每档 90 秒。到时取消在途请求，不排空。主吞吐由 Decode generation token counter 在前 30 秒之后的采样差分计算；计入窗口内生成的 token，不只统计完成请求。每卡实际吞吐按各 DP rank counter 记录。客户端单请求 TPS 使用自然完成请求，另提供完全落在稳态窗口内的请求统计。所有原始样本保存在本实验目录，未加入 Git。

候选唯一部署差异为 DeepGEMM 扩展的只读 bind mount；模型、镜像、启动参数、EPLB 和图模式不变。补丁选择 B300/EP8/E400/top-k6 下 160–200 tokens/rank 的 M64 分块。候选源码基于 `1e1842a833699298f7afc02eefb2ed168fff6938`；运行包 79 个 Python/API/kernel header 文件与该源码哈希一致。扩展针对当前 CPython 3.12、Torch 和 CUDA 13 构建，并先通过 8 卡输出逐元素一致性测试。

基线首轮部分 Prefill 指标缺失（跨机端口不可达，已改为 TY18 本机采集）；Decode 指标与客户端请求记录完整。缓存命中仍从请求 usage 独立计算。

## 启动与复现

基线：`docker compose -f /data/services/tuoyu-cep8-dev-20261028/service-r22/TY19.compose.yaml up -d --no-deps decode`。

候选额外添加 `-f /data/services/tuoyu-dep8-moe-ab-20261029/candidate.override.json`，把同目录 `candidate.so` 只读挂载到 `/usr/local/lib/python3.12/dist-packages/vllm/third_party/deep_gemm/_C_extension.abi3.so`。`prepared.json` 保存原版/候选二进制 SHA256 和 image ID。不覆盖镜像内原文件。

客户端：`run-phase.py baseline` / `run-phase.py candidate`。使用容器 `tuoyu/vllm-bench:cpu-light`，两分片，各 3 CPU/4GiB，原始请求记录和采样归档位于各 phase/results。`analyze.py PHASE` 重建所有分位数、per-request CSV、per-rank TPS 和投机解码统计；`compare.py` 生成本表。默认启动与模型完整配置见已有 DEP8 baseline 文档。
